    Define the deps object (everything injected — no globals):
    ```
    export interface ExtractDeps {
      db: Database.Database;
      messageCreate: MessageCreate;
      model: string;
      system: string;            // the extraction system prompt (caller builds it)
      now?: () => Date;
      log?: (msg: string) => void;
    }
    export interface ExtractOutcome {
      result: ExtractionResult | null;
      fromCache: boolean;
      apiCalls: number;
      skipped: boolean;
    }
    export async function extractOne(deps: ExtractDeps, rawText: string): Promise<ExtractOutcome>;
    ```
    Algorithm (keep the cache strictly BEFORE the API call — correctness requirement, not optimization):
    1. `const key = contentHash(rawText)`.
    2. `const cached = getCachedExtraction(deps.db, key)`. If non-null: `const parsed = ExtractionResultSchema.safeParse(cached)`; if success return { result: parsed.data, fromCache:true, apiCalls:0, skipped:false }. (If a cached blob somehow fails validation, treat as miss and fall through — defensive, but normal path is success.)
    3. Cache miss: define an inner `attempt()` that does `const raw = await callClaude(deps.messageCreate, { model: deps.model, system: deps.system, userText: rawText }); return ExtractionResultSchema.safeParse(raw);`.
    4. First attempt. If success → putCachedExtraction(db, { contentHash:key, resultJson: parsed.data, model: deps.model, extractedAt: (deps.now?.() ?? new Date()).toISOString() }); return apiCalls:1.
    5. If failure → second attempt. If success → put + return apiCalls:2. If failure → log `extractOne: validation failed twice, skipping item (hash ${key.slice(0,8)})` via deps.log; return { result:null, fromCache:false, apiCalls:2, skipped:true }. Do NOT cache a failed parse.
    6. Let any thrown error from callClaude (no tool_use / network) propagate — caller decides pending-vs-failed. Do NOT wrap-and-swallow API errors as skips.

    Store the validated `parsed.data` as result_json so cache replay re-derives identical vacancies. (Storing the parsed shape is fine — it round-trips through ExtractionResultSchema on the next hit.)

Keep it concise.

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-04 | Tampering / Elevation (prompt injection) | extractor.ts system prompt + raw post text | mitigate | Output is schema-constrained via forced tool-use (input_schema) AND re-validated with ExtractionResultSchema; injected instructions in a post cannot widen the output shape or insert fields outside the contract. Low residual risk — note in summary |
| T-03-05 | Information disclosure | client.ts / extractor.ts logging | mitigate | Never log ANTHROPIC_API_KEY or full raw post body or full model response at info level; skip-log uses only the first 8 chars of the content hash. Assert no `console.log(rawText)` / key logging in code |
| T-03-06 | Denial of service (cost runaway) | extractor.ts cache gate | mitigate | getCachedExtraction runs BEFORE callClaude; retry is capped at exactly one extra call; hard errors propagate (no infinite retry). Verified by the 0-call cache-hit test and apiCalls<=2 assertions |
