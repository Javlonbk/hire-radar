    - A test with one adapter that throws and one that succeeds asserts: the second still ran, the failed source has an error and unchanged cursor, the succeeding source advanced its cursor.

Create `src/pipeline/orchestrator.ts`:
```typescript
export interface IngestOptions {
  db: Database.Database;
  adapters: SourceAdapter[];
  sinceOverride?: Date;          // from future --since flag (Phase 4 wires the CLI)
  now?: () => Date;              // injectable clock for tests; default () => new Date()
  log?: (msg: string) => void;  // default console.log
}
export interface SourceStat { sourceId: string; fetched: number; inserted: number; error?: string; }
export async function ingestSources(opts: IngestOptions): Promise<SourceStat[]>
```

Logic, looping adapters in order:
1. `const runStart = now();`
2. For each `adapter`:
   - `const cursor = getCursor(db, adapter.id);`
   - `const since = sinceOverride ?? (cursor ? new Date(cursor) : new Date(runStart.getTime() - 7*24*60*60*1000));` (7-day backfill default)
   - Wrap the rest in try/catch:
     - `const items = await adapter.fetch(since);` (async work BEFORE any transaction — PITFALL-10)
     - `const inserted = persistRawItems(db, items);` (persist-before-cursor — SRCE-05)
     - `upsertCursor(db, adapter.id, adapter.id.split(':')[0], JSON.stringify({}), runStart.toISOString());` (cursor advances ONLY after persist succeeds)
     - push `{ sourceId: adapter.id, fetched: items.length, inserted }`
     - `log(adapter.id + ": " + items.length + " fetched, " + inserted + " new")`
   - catch `err`: push `{ sourceId: adapter.id, fetched: 0, inserted: 0, error: errMessage }`; `log(adapter.id + ": ERROR " + errMessage)`; do NOT upsertCursor (PITFALLS UX — print source-by-source, continue on failure).
3. Return the stats array.

Use `adapter.id.split(':')[0]` as the `type` column value (hh | rss | telegram).

Tests inject a fake `db` via `openDatabase(':memory:')`, a fixed `now`, and stub adapters (one resolving with 2 RawItems, one rejecting). Assert: both stats present, failed source has `error` set and `getCursor` for it returns null (unchanged), succeeding source `getCursor` equals runStart ISO. Assert raw_items row count == inserted for the succeeding source. First-run test: stub adapter records the `since` it was called with; assert it is within a few seconds of runStart - 7d.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| adapter.fetch() result → orchestrator | RawItems from adapters (untrusted external content) cross into persistence |
| sinceOverride (future CLI input) → adapter | User-supplied date controls the fetch window |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-07 | Denial of Service | one failing adapter | mitigate | Per-source try/catch isolates failures so one bad source cannot abort the whole run (SRCE-04); cursor stays put so the next run retries |
| T-02-08 | Tampering | persist-before-cursor ordering | mitigate | persistRawItems runs inside a synchronous transaction (PITFALL-10) before upsertCursor, guaranteeing a crash mid-run leaves fetched raws intact and the cursor un-advanced (SRCE-05) |
| T-02-09 | Information Disclosure | orchestrator log output | mitigate | Per-source log lines emit only id + counts + error message, never full RawItem payloads or any secret-bearing config |
</threat_model>
