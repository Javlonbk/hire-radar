normalize(text) transform order (PITFALL-7 / FNDN-03):
  1. text.normalize('NFC')         -- collapse Cyrillic/Latin homoglyph code points to canonical form
  2. trim + collapse internal whitespace runs to single spaces
  3. toLowerCase()

contentHash(text): SHA-256 hex digest of normalize(text), via node:crypto createHash('sha256').

IMPORTANT on homoglyphs: NFC alone does NOT merge a Latin 'o' (U+006F) and a Cyrillic 'о' (U+043E) — they are distinct code points, not canonical equivalents. FNDN-03 / Success Criterion 3 requires uz-Latn vs uz-Cyrl variants to hash identically. The normalize() function MUST therefore ALSO map the common confusable Cyrillic letters that share a glyph with Latin (а→a, е→e, о→o, р→p, с→c, у→y, х→x, and uppercase forms) to their Latin counterparts BEFORE hashing. Build a small confusable-folding map covering at minimum: а/А, е/Е, о/О, р/Р, с/С, у/У, х/Х → Latin a/e/o/p/c/y/x. Document this map with one WHY-comment. Test must prove that the Cyrillic-spelled and Latin-spelled variants of the same word produce the same hash.

Config shape (Zod 4 — STACK.md requires zod ^4):
  Secrets (env ONLY, never from file — ARCHITECTURE Anti-Pattern 4):
    ANTHROPIC_API_KEY      (required, non-empty string)
    TELEGRAM_API_ID        (required for telegram; number)
    TELEGRAM_API_HASH      (required for telegram; non-empty string)
    TELEGRAM_SESSION       (optional string — empty until first auth)
  Non-secret (from JSON config file, shape per config.example.json from Plan 01):
    telegram.channels: string[]
    hh: { area: string, text: string, perPage: number }
    rss.feeds: string[]

loadConfig(opts?: { configPath?: string, env?: NodeJS.ProcessEnv }) merges file + env,
validates with a Zod 4 schema, and on failure throws an Error whose message names the
missing/invalid field, e.g. "Missing required env var ANTHROPIC_API_KEY — set it in your .env file".
Accept an injectable `env` param so tests don't mutate the real process.env.
