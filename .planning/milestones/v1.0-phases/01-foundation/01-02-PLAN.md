| Boundary | Description |

| filesystem → SQLite file | The DB file holds all ingested data; its location and permissions matter |
| concurrent CLI invocations → single DB | Two `ingest` runs may contend for the write lock |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-01-04 | Denial of Service | Concurrent CLI writers crash with SQLITE_BUSY | mitigate | `PRAGMA journal_mode=WAL` + `busy_timeout=10000` set on every connection (Task 2); the second writer waits instead of crashing (PITFALL-9) |
| T-01-05 | Tampering | Partial/corrupt writes from async-in-transaction | mitigate | `runInTransaction` is strictly synchronous; tested for atomic rollback on throw (PITFALL-10, Task 2) |
| T-01-06 | Information Disclosure | DB file world-readable on shared host | accept | Single-user local CLI; DB lives in git-ignored `data/`; OS default file perms acceptable for v1, no PII secrets stored in DB |
