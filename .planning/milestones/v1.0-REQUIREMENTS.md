# Requirements: Hire Radar

**Defined:** 2026-06-13
**Core Value:** Run `hire-radar ingest` and reliably end up with clean, structured, deduplicated vacancies in SQLite — no matter how messy the source posts are.

## v1 Requirements

Requirements for initial release. Each maps to roadmap phases.

### Foundation

- [x] **FNDN-01**: Vacancies, raw items, extraction cache, and source cursors persist in a SQLite database (WAL mode) with raw payload retention for debugging
- [x] **FNDN-02**: User can configure Telegram credentials, channel whitelist, hh.uz filters, RSS feed URLs, and Anthropic API key via config file/env without touching code
- [x] **FNDN-03**: Content hashing normalizes text (NFC, trim, lowercase) before SHA-256 so Cyrillic/Latin homoglyph variants hash identically

### Source Adapters

- [x] **SRCE-01**: User can ingest vacancies from hh.uz via its official REST API with pagination and incremental fetch (only new postings since last run)
- [x] **SRCE-02**: User can ingest vacancies from configured RSS feeds with conditional GET (ETag/If-Modified-Since) and non-UTF-8 encoding support
- [x] **SRCE-03**: User can ingest posts from whitelisted Telegram channels via gramjs user-bot with persistent session, message-id watermark, and FloodWait retry
- [x] **SRCE-04**: A failure in one source does not abort ingestion from other sources; each source reports its own outcome
- [x] **SRCE-05**: Raw items are persisted before extraction so interrupted runs resume without re-fetching

### AI Extraction

- [x] **EXTR-01**: Claude Haiku extracts structured vacancies (title, company, skills, salary min/max/currency, location, remote type, apply contact, language) from raw posts in uz-Latn, uz-Cyrl, ru, and en
- [x] **EXTR-02**: Extraction handles multiple jobs in one post (array output) and rejects non-job posts (`is_job_post` gate) without fabricating fields
- [x] **EXTR-03**: Extraction results are cached by content hash — identical text is never sent to the API twice
- [x] **EXTR-04**: Duplicate vacancies (same normalized title + company + description prefix) are detected by hash and not inserted twice

### CLI

- [x] **CLI-01**: User can run `hire-radar ingest` to fetch, extract, and persist from all (or selected) sources, with per-run stats (fetched, extracted, deduped, skipped, cost-relevant API calls)
- [x] **CLI-02**: User can run `hire-radar list` with filters (source, skill/keyword, date range, limit) to browse vacancies in the terminal
- [x] **CLI-03**: User can run `hire-radar export` to dump structured vacancies as JSON with the same filters as list
- [x] **CLI-04**: User can run a one-time Telegram auth command that produces a persistent session string

## Out of Scope

Explicitly excluded. Documented to prevent scope creep.

| Feature | Reason |
|---------|--------|
| User matching, match scores, notifications | Kasbim Phase 1 features; this project is ingestion only |
| Always-on daemon / internal scheduler | CLI on demand; system cron covers scheduling |
| Web UI / API server | DB + CLI is the interface |
| LinkedIn scraping | Prohibited — ToS/legal risk, same rule as kasbim |
| Embedding dedup in v1 | Breaks cost model; hash dedup catches exact reposts free |
