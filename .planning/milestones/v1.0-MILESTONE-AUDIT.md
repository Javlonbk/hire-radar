## Definition of Done

Run `hire-radar ingest` and reliably end up with clean, structured, deduplicated vacancies in SQLite — no matter how messy the source posts are — with `list`/`export` to retrieve them and a one-time `auth` for Telegram.

## Cross-Phase Integration — 16/16 wired, 4/4 E2E flows complete

- **ingest E2E:** `bin/hire-radar` → `buildAdapters(config)` → `ingestSources` (fetch → `raw_items`, fully awaited) → `extractPending` (reads pending raws → Claude tool-use → `vacancies`) → stats block. SRCE-05 raw-before-extract ordering confirmed.
- **list/export:** both read via the single `queryVacancies` helper; `lang` column flows schema → insert → query → output.
- **auth → adapter:** session string from `auth` → `TELEGRAM_SESSION` env → config → `buildAdapters` → Telegram adapter.
- **config:** `loadConfig` consumed consistently by adapters (Phase 2), extractor (Phase 3 model/key), and CLI (Phase 4).

Build: `tsc --noEmit` clean. Tests: 175/175 pass across 22 files.

## Integration Findings Resolved Inline

Two cross-phase first-run usability warnings (only visible at the milestone boundary) were fixed during the audit:

- **INT-01** — `.env` files were silently ignored despite dotenv being a dependency and error messages referencing `.env`. Fixed by loading `dotenv/config` at the bin entry (commit 7ae91bc).
- **INT-02** — `hire-radar auth` (the first command a new user runs) spuriously required `ANTHROPIC_API_KEY`. Fixed so auth depends only on the Telegram API credentials (commit a327db6).

## Tech Debt (non-blocking, tracked)

- `src/index.ts` `APP_NAME` dead export (bootstrap stub) — harmless.
- `vacancies.posted_at` column + index declared but never populated; filtering uses `created_at` — dead schema weight, candidate to either populate from source data or drop in v2.
- DB path fixed at `data/hire-radar.db` (not configurable) — accepted v1 choice; add `--db`/config override if multi-DB usage emerges.

## Deferred to v2 (per project Out of Scope)

Embedding/semantic dedup, Playwright scrapers (OLX/jobs.uz, career pages), Anthropic Batch API cost optimization, daemon/scheduler, user matching/notifications, web UI.
